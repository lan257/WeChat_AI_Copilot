## 2. 不变的边界

- **M1 读取，M2 管理消息，M3 记忆与查询，M4 Agent，M5 Web，M6 基础设施。** 六逻辑模块，不是六微服务。
- Windows 微信本机可读取是外部前提；首版文本/单采集目标；历史补录限定在已验证 POC 技术范围内。
- Agent 无微信发送、任意 SQL、任意 Shell 或其它联系人越权检索；用户在微信手动发送。
- 工作区有聊天消息区和 AI 自由咨询侧栏；极简模式默认仅 `展开 + 三条点击复制建议 + 人设轮换 + 换一批`。
- 对每个有效账号/会话/namespace，初始化默认较小的数字 sender ID 为本人并记录为待确认；“互换身份”只改变预览，“确认身份”才提交当前候选。不把默认规则写成跨账号事实。
- 用户确认 sender ID 前不更新人物画像或消息抽取的长期记忆。首次确认后立即执行第一次沉淀；之后画像和自动长期记忆共用未沉淀文本窗口，严格超过 5,000 字时一次性沉淀并推进游标。再次互换须重新确认，旧版本派生内容失效并重建，人工记忆保留；不采用定时或手动强制刷新。
- 画像/记忆主体是微信参与者及其账号/会话范围，不是当前登录 Web 的操作用户；画像摘要保留来源消息和 perspective version。
- 不跨 shard/不同来源盲目合并，保留来源信息与 `NeedsReview`，不因本地历史缺失删除服务端消息。

## 3. 来源/证据边界

主要依据：2026-10-09 的总体设计；`history-backfill-poc-report.md`（单会话、单 shard、92 条历史文本，5/5 ID 匹配，隔离库幂等）；`history-backfill-source-mapping.md`；此前实时采集 POC 记录。上述报告是**已有资料的实测陈述**，本包没有重新运行微信读取器、访问私人仓库或检验 Agent 真模型。

实际开发前需对仓库里的现有 DTO、API、数据库迁移与本设计进行差异清点；**不得因详细设计中提供了示意 DTO 就擅自重置或破坏已运行的 POC 数据库**。
