# V8.1 候选（在 V8 之上只增加一项：采集故障显示态）

状态：**待用户审核批准**。批准之前，正式前端 `wwwroot/v8/` 不实现这一状态。

- 基线：`V8/WeChat_AI_Copilot_Product_Prototype_V8.html`（SHA-256 `f57fe56b…fe9b3ee`），逐字节作为起点，只加入下面 5 处改动。
- 本候选：`WeChat_AI_Copilot_Product_Prototype_V8.1.html`（SHA-256 `b6cfba799a3df3b124cd7795f433758fc902deaf6b90b1d0e4243f36e6d7b221`）。

## 为什么提出这一改动

真实数据验收时，被监听联系人的采集状态一度是 `Error`（读取器与本机数据库之间的目标集合冲突），但页面顶部仍显示“监听待就绪”，列表小圆点也仍是普通灰色。使用者看到的是一个“正常等待”的界面，实际却已经停止采集，新消息不会进入上下文。V8 原型只有“监听中 / 未监听”两态，没有给故障留位置，所以这一状态无法在正式代码里凭空实现，必须先改 Demo。

## 具体改动（共 5 处）

1. 顶部状态胶囊新增第三态：采集异常（琥珀红底 `#fdefec` / 字色 `#a4523c`），优先级高于“监听中 / 未监听”。
2. 会话头像右下角小圆点新增 `.fault-mini`（`#d98a6a`），与“监听中”的绿点、“未监听”的灰点并列。
3. 聊天区顶部新增 `#captureBanner` 横幅，仅在故障时出现，文案为“该联系人的本机采集已中断，历史消息仍可阅读，新消息不会进入上下文。”，右侧按钮跳到「设置 → 应用与状态 → 运行状态」，与既有身份校准横幅同一形态。
4. 故障判定沿用现有 `x.listen` 语义：故障只改变显示，不改变“是否监听”的数据本身。
5. 演示数据里给 `june` 一位联系人标上 `fault:true`，使该状态无需真实设备即可复核。

## 没有改动的部分

三条回复建议的位置、人设与分析深度共用规则、极简模式折叠范围、设置中心四个分组与子页返回、Skills 生命周期、历史补录范围与统计、连接向导、文案措辞与配色体系全部保持 V8 原样。

## 批准后正式代码要做的对应改动

`wwwroot/v8/chat.js` 的 `renderHeader` 与 `renderDirectory` 按 `captureState==='Error'`（以及 `reader_status` 的故障码）显示上述状态，并在 `v8/index.html` 增加 `#captureBanner`；服务端已提供 `captureState`，不需要新增接口。
