# V8.2 候选（在 V8 之上只增加一项：历史补录的范围选择与续扫可见性）

状态：**待用户审核批准**。

- 基线：`V8/WeChat_AI_Copilot_Product_Prototype_V8.html`（SHA-256 `f57fe56b09f3655333f25c2c0f20e59c9717a7948f1c07cc2d50431a6fe9b3ee`），逐字节作为起点，只加入下面 5 处改动。
- 本候选：`WeChat_AI_Copilot_Product_Prototype_V8.2.html`（SHA-256 `556e9fd53bc80c9ab330f6a27d62a06732e0d6973d7d129de4c9d583a0100e51`）。
- 与 V8.1 候选相互独立：V8.1 只加“采集异常”显示态，本候选只改「历史补录」页；两者都从同一 V8 基线出发，可分别批准或分别否决。

## 为什么提出这一改动

真实数据验收中，使用者的联系人在微信里存有跨年度记录，但补录页只给“最近 90 天 · 最大 5,000 条”，
既无法请求更早的范围，也无法看出“上次扫到哪里、这次是不是接着扫”。读取器已经改成 keyset 分页流式导入，
但界面仍把补录描述成一次性小任务，与实际能力不符。

## 具体改动（共 5 处，全部在「设置 → 联系人与会话 → 历史补录」内）

1. 补录范围新增第二张卡片「本机全部历史 · 不限时间窗口 · 单次最多 200,000 条 · 中断后从已入库位置续扫」。
2. 动作区在「同步历史消息」与「重置演示」之间新增 `backfill-full` 按钮「导入本机全部历史」，运行中同样禁用。
3. 顶部提示改写：不再声称“完成不代表微信历史完整”这种无法自证的措辞，改为“完成只代表所选范围的扫描完成；本机更早时段是否存在记录，由微信本地库决定”。
4. 统计区在任务进行中/完成后显示一行续扫提示：“续扫：本机该范围累计已扫描 N 条，含此前中断的扫描”，N 为游标累计值加本次进度。
5. 完成文案按范围区分：有界窗口仍写“本次有界扫描完成”，全量任务写“本机可读历史已全部扫描完成”。

## 没有改动的部分

三条回复建议、人设与分析深度共用规则、极简模式折叠范围、设置中心分组与子页返回、Skills 生命周期、
监听目标上限、身份校准流程、连接向导、配色与文案体系全部保持 V8 原样。演示数据只在 `backfill`
状态对象里多了 `full` 与 `resumedFrom` 两个字段，用于表现续扫。

## 已在浏览器验证

用真实点击走完「设置 → 联系人与会话 → 历史补录 → 导入本机全部历史」：两张范围卡片与两个按钮都出现，
点击后进度推进，续扫提示按预期显示（演示值 4,200 起步，最终累计 4,331 条），完成后文案变为
“本机可读历史已全部扫描完成”。无控制台错误，页面渲染与 V8 基线一致。

- `Modules/Conversations/Api/HistoryJobEndpointsV1.cs`：`fullLocalHistory` 创建入口、无窗口任务的空范围、
