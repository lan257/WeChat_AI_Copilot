# WeChatAiCopilot API

ASP.NET Core host for the formal product. It serves the workspace UI and the versioned Reader, conversation, message, and sender-perspective APIs.

## Configuration

- `ConnectionStrings__FormalDatabase`: optional PostgreSQL connection. When set, startup applies pending migrations from this repository. When absent, the host starts without database access and `/health/ready` reports that it is not ready.
- `Authentication__ReaderBearerToken` and `Authentication__WebBearerToken`: separate API credentials.
- `Reader__AllowedAccountExternalId` and `Reader__AllowedConversationExternalId`: the single account and conversation accepted from the local Reader.
- `Web__AllowedAccountExternalId` and `Web__AllowedConversationExternalId`: the single account and conversation exposed to the workspace.
- `Reader__Provider` and `Web__Provider`: provider identifiers; both default to `local-wechat`.
- Agent execution fails closed unless `Agent:Runtime` is explicitly set to `Fake` or `CodexCli`. Missing or unrecognized values do not register a runtime.
- `Agent:Runtime=Fake` enables deterministic demonstration-only replies and consultations. Fake suggestions carry a visible `FakeRuntime` marker and are not generated by a model.
- For local Codex CLI execution, set `Agent:Runtime=CodexCli`. The shared M6 executor is exposed to business modules only as `IStructuredCodexCliExecutorV1.ExecuteAsync(prompt, schema, timeout)`; it owns executable discovery, process arguments, a temporary working directory, stdin, the minimal environment, output bounds, and cleanup. Set `Platform:CodexCli:ExecutablePath` to override the default `codex`; the old `Agent:CodexCli:ExecutablePath` remains a fallback. Non-empty host `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` (including lowercase variants) are forwarded to the CLI process when explicitly set; no proxy address is supplied by the application. A non-empty host `CODEX_HOME` is preserved; otherwise the executor derives `<USERPROFILE>/.codex` on Windows or `<HOME>/.codex` on Unix, falling back to the other home variable when needed. If neither user-home variable nor an explicit `CODEX_HOME` is available, execution fails closed. Only the path is passed to the CLI; the API never reads or logs auth-file contents or the path. npm `.ps1`/paired `.cmd` shims are resolved to their adjacent `node_modules/@openai/codex/bin/codex.js` and Node executable, so CLI flags are passed as argv and never parsed by PowerShell. Missing Node or the CLI JS entry point fails closed. Suggestions schemas keep provider constraints minimal; the runtime enforces exactly three distinct, non-empty candidates locally. Sanitized run errors distinguish process start, non-zero exit, missing structured output, and invalid structured output; raw stderr and prompts are never logged. The current adapter was checked against local Codex CLI 0.161.0 using help-only commands and a synthetic `status=ok` smoke; no chat data was used.
- Agent tasks also require `Agent:AllowedPersonaPresetIds`, `Agent:SkillVersion`, `Agent:Budget:MaxDurationSeconds`, `Agent:Budget:MaxContextCharacters`, and `Agent:Budget:MaxToolCalls`. Consultation history defaults to at most 8 prior turns and 4,000 characters; configure `Agent:ConsultationHistory:MaxTurns` (1–100) and `Agent:ConsultationHistory:MaxCharacters` (1–100,000) to adjust those bounds.
- `GET /api/ai/personas` lists only supported, configured persona IDs and labels. Prompt instructions remain server-owned. The Codex adapter sends the clipped current M3 context and bounded same-thread consultation history through stdin; it uses an empty temporary working directory, an output schema, read-only sandbox, ephemeral mode, and temporary output cleanup. It disables the shell tool, multi-agent, remote plugins, MCP servers, and web search. Authentication remains owned by the local CLI through `CODEX_HOME`; the API does not read or log credentials.
- M4 binds the M3 read-only context-tool session to the authorized conversation. For consultations, Codex may request bounded `searchHistory` and `getMessageEvidence` actions only when the corresponding `Agent:AllowedReadCapabilities` and `Agent:Budget:MaxToolCalls` allow them. The coordinator injects the scope-bound session; prompt and tool request DTOs contain no account/conversation IDs. Search/evidence calls pin the M3 message-set revision, validate anchors and IDs, and the runtime rechecks the context revision before returning the answer. Prior-turn evidence must be looked up again before the answer can cite it. With no tool session or capability, the runtime uses only the already supplied context and same-thread consultation history.

The server does not accept account or conversation selection from API request bodies to widen these configured scopes. The UI exposes only read and calibration actions; it does not send WeChat messages.

## Endpoints

- `GET /health/live`, `GET /health/ready`
- `POST /api/reader/messages`, `POST /api/reader/history-batches`
- `GET /api/conversations/current`, `GET /api/conversations/current/messages`, `GET /api/conversations/current/sender-perspective`
- `PUT /api/conversations/current/sender-perspective`
- `GET /api/conversations/current/memory`, `POST /api/conversations/current/memory`
- `GET`, `PUT`, and `DELETE /api/conversations/current/memory/{memoryId}`
- `GET /api/ai/personas`
- `POST /api/ai/suggestions`, `GET /api/ai/suggestions/{batchId}`
- `POST /api/ai/consultations`, `GET /api/ai/consultations/{threadId}`, `POST /api/ai/consultations/{threadId}/turns`
- `GET /api/ai/runs/{runId}`
